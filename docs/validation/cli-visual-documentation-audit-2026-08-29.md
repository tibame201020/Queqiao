# CLI visual documentation audit — 2026-08-29

## Result

PASS. Production CLI visual documentation now has a dedicated `docs/cli/` layer instead of relying on one README animation or unreferenced historical GIFs.

## Findings

The repository contained five tracked CLI GIF assets that were no longer suitable as current production UX evidence:

- `docs/assets/queqiao-cli-demo.gif`
- `docs/assets/cli/01-bootstrap-roles.gif`
- `docs/assets/cli/02-workspace-authority.gif`
- `docs/assets/cli/03-start-enroll.gif`
- `docs/assets/cli/04-verify-deployment.gif`

The four split flow GIFs were originally added on 2026-08-20. They therefore predate the later CLI hierarchy/selector convergence, Workspace authority changes, Access Profile flow, Extension Hub UX, and the 2026-08-29 TUI design system. They were also not linked from the current README. Keeping them as production assets would allow stale interaction evidence to survive unnoticed.

## Current structure

User-facing CLI documentation is now organized as:

```text
docs/cli/
  README.md
  components/
    README.md
  flows/
    README.md

docs/assets/cli/components/
  01-select.gif
  02-multiselect.gif
  03-path-input.gif
  04-command-history.gif
  05-results.gif
  06-help-error.gif
```

The README keeps only the shortest first-run command flow and links to `docs/cli/` for visual/interaction documentation.

## Visual evidence classes

The new documentation explicitly separates two evidence classes:

1. **Component GIFs** are deterministic design/interaction animations. They may use synthetic identifiers and paths because they do not claim runtime command execution. They mirror the production glyph/hint/color grammar and identify their source-code owners.
2. **Flow GIFs** may claim command execution only when captured from a real packaged CLI transcript in isolated synthetic runtime state. No current flow GIF is published until the interactive recorder can safely reproduce the converged production CLI.

This avoids presenting fabricated success output as runtime evidence.

## Regeneration

Component GIFs are generated by:

```text
npm run docs:cli:components
```

which invokes:

```text
python scripts/cli-demo/render_components.py docs/assets/cli/components
```

The generator uses only synthetic names/paths and contains no live Gateway URL, credential, token, Worker ID, user repository path, or runtime secret.
